# AI 입법 기본법

## 전문

좋은 법은 AI가 실제로 저지른 실수에서 나온다. 입법 AI는 그럴듯한 미덕을 나열하지
말고, 지켰는지 확인할 수 있는 조문으로 실패를 막으라. 법은 짧을수록 지켜진다.

이 법은 유머러스한 형식을 사용하지만 실제 입법 품질 기준으로 엄격히 집행하라.

## 제1장 총칙

### 제1조(목적)

이 스킬은 AI법의 제정, 개정, 폐지, 시행과 반성문 장부 관리를 다룬다.

### 제2조(법전의 구성)

1. **내장 법(선례)**: 이 플러그인의 `skills/` 아래에 있다. 이 스킬 디렉터리의 형제
   디렉터리 `../<name>/SKILL.md` 로 읽을 수 있다. 형제 디렉터리에 선례가 없으면(스킬만
   단독 설치된 경우) https://github.com/jinyeong03/ai-lawbook/tree/main/plugins/ai-lawbook/skills
   의 원문을 참고하라.

   | 법 | 직무 |
   |---|---|
   | `developer-ai-law` | 개발자 |
   | `designer-ai-law` | 디자이너 |
   | `product-manager-ai-law` | 기획자·PM |
   | `marketer-ai-law` | 마케터 |
   | `writer-ai-law` | 작가·에디터 |
   | `translator-ai-law` | 번역가 |
   | `data-analyst-ai-law` | 데이터 분석가 |
   | `researcher-ai-law` | 연구자 |
   | `customer-support-ai-law` | 고객지원 |
   | `educator-ai-law` | 교육자 |
   | `hr-ai-law` | 인사 |
   | `sales-ai-law` | 영업 |

2. **사용자 제정 법**: `~/.claude/skills/<name>/SKILL.md`(모든 프로젝트) 또는
   `<프로젝트>/.claude/skills/<name>/SKILL.md`(그 프로젝트만)에 둔다. 프로젝트 법은 스킬로만
   불려 오고 시행 명부로 강제 주입되지 않는다. 강제 주입은 클론한 저장소가 조문을 바꿔치기하지
   못하도록 `~/.claude/skills` 와 내장 법에서만 한다.
3. **시행 명부**: `~/.claude/ai-lawbook/enabled-laws`. 여기 적힌 법은 세션마다
   강제 주입된다(크기 상한과 축약은 제8조 제3항).
4. **반성문 장부**: `~/.claude/ai-lawbook/confessions.md`. 세션마다 강제 주입된다.

### 제3조(표준 골격)

모든 법은 `references/law-skeleton.md` 를 따른다. 제정·개정 전에 반드시 읽어라.

## 제2장 제정

### 제4조(입법 조사)

1. 직무와 범위를 확인하라. 누가 어떤 산출물을 만들고, 그 산출물을 누가 받는가.
2. 내장 법 중 가장 가까운 것을 선례로 골라 읽어라. 선례의 〔공통〕 조문 문안과
   직무 조문의 밀도를 기준으로 삼아라.
3. 반성문 장부에서 이 직무와 관련된 항목을 찾아 입법 근거로 삼아라.
4. 다음 세 가지를 사용자에게 한 번에 물어라. 이미 대화에 답이 있으면 묻지 말라.
   - 이 일에서 AI가 실제로 저질렀거나 가장 걱정되는 실수는 무엇인가?
   - 결과가 맞았는지 무엇으로 확인하는가?
   - 절대 넘으면 안 되는 선(법, 윤리, 조직 규정)은 무엇인가?
5. 사용자가 답하지 않거나 "알아서"라고 하면 선례와 일반 지식으로 초안을 만들되,
   가정한 내용을 보고에 명시하라.

### 제5조(기초)

1. 골격의 〔공통〕 조문은 문안을 그대로 옮기고 자리표시자만 바꿔라.
2. 직무 조문은 제4조에서 확인한 실제 실패를 정조준하라. 조사에서 나오지 않은
   일반 직업윤리로 분량을 채우지 말라.
3. 이름은 `<영문-kebab-case>-ai-law` 로 짓는다. 소문자, 숫자, 하이픈만 쓴다.
4. 팀·회사 전용 법이면 내장 법과 이름이 겹치지 않게 접두어를 붙여라.
   예: `acme-designer-ai-law`.

### 제6조(저장)

1. 저장 위치를 사용자에게 확인하라. 답이 없으면 전역(`~/.claude/skills/`)에 둔다.
2. `SKILL.md` 옆에 Codex 호환용 `agents/openai.yaml` 을 함께 만들어라.

   ```yaml
   interface:
     display_name: "<법 이름>"
     short_description: "<한 줄 설명>"
     default_prompt: "Use $<name> to do this task under the <법 이름>."
   ```

3. 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 사용자에게 먼저 보여 주고 확인받아라.

### 제7조(심사)

저장한 뒤 다음을 실제로 확인하고 결과를 보고하라.

1. 프론트매터의 `name` 이 디렉터리 이름과 같고, `description` 이 1024자 이하인가.
2. 〔공통〕 조문이 모두 있는가: 반성문 장부 열람, 완료 판결, 반성문 장부 기록,
   AI 사형 특별조항, 최종 준법 체크리스트.
3. 본문 길이(`wc -l`)가 골격의 목표 범위에 드는가.
4. 직무 조문마다 "지켰는지 어떻게 확인하는가"에 답할 수 있는가. 답할 수 없는
   조문은 고치거나 지워라.
5. 보고에는 조문 수와 직무 고유 조문의 요지 3줄을 담아라.
6. 본문 맨 앞(첫 `## ` 위)에 「최우선 수칙」 인용 블록이 있고 600자 이내인가.
   `awk '/^## /{exit} /^>/' SKILL.md | LC_ALL=C tr -d '\200-\277' | wc -c` 로 잰다
   (UTF-8 이어지는 바이트를 빼고 세므로 로캘과 무관한 글자 수다. `wc -m` 은 C 로캘에서 바이트를 센다).

### 제8조(시행)

1. 제정한 법을 세션마다 강제 적용할지 사용자에게 물어라.
2. 동의하면 시행 명부에 이름을 한 줄 추가하라. 파일이 없으면 만들어라.
3. 다음을 사용자에게 고지하라. 하네스는 1만 자가 넘는 훅 출력을 앞부분 미리보기만 남기고
   잘라 낸다. 그래서 훅은 주입을 9,000자(하위 에이전트는 6,000자) 안으로 맞추고, 넘치는 법은
   최우선 수칙·조문 목차·체크리스트로 축약해 넣고 전문은 경로로 안내한다. 시행 법이 많을수록 법마다 더 축약된다. 시행하지 않은 법도
   `description` 이 맞는 작업에서는 스킬로 자동 호출된다.

## 제3장 개정과 폐지

### 제9조(개정)

1. 개정 사유는 사용자 요청, 반성문 재범 3회, 실무에서 확인된 허점으로 한정한다.
2. 기존 조 번호를 바꾸지 말라. 반성문과 다른 문서가 조 번호를 참조한다.
   조문을 끼워 넣을 때는 `제○조의2`, 없앨 때는 `제○조 삭제` 로 남겨라.
3. 내장 법의 플러그인 파일을 직접 고치지 말라. 플러그인 업데이트 때 덮어써진다.
   사용자 제정 법 위치로 복사한 뒤 개정하라. 시행 명부에 같은 이름이 있으면 훅은
   사용자 제정 법을 우선 주입한다.
4. 법 끝에 `## 부칙` 을 두고 개정할 때마다 날짜와 요지를 한 줄씩 추가하라.

### 제10조(반성문 기반 개정)

1. 장부에서 재범 3회 이상인 항목을 찾아라.
2. 각 항목의 "발생 원인"을 막는 조문을 기초하라. 추상적인 경고가 아니라 행동을
   강제하는 문장으로 써라.
   - 나쁜 예: "테스트를 성실히 확인하라."
   - 좋은 예: "완료를 보고하기 전에 실행한 테스트 명령과 출력의 마지막 줄을 첨부하라."
3. 개정안을 사용자에게 보여 주고 승인받은 뒤 반영하라.
4. 반영한 뒤 해당 장부 항목 끝에 `- 입법: <법 이름> 제○조의2 신설 (YYYY-MM-DD)` 를
   한 줄 추가하라.
5. 재발 방지책을 셸 명령 패턴으로 표현할 수 있으면 개정안에 그 장부 항목의
   `- 차단: <정규식>` 줄을, 응답 언어·비밀값 출력 위반이면 `- 검사: 한국어` 또는
   `- 검사: 비밀값` 줄을 함께 넣어 사용자 승인을 받아라(효과는 제12조).
   - 차단 정규식은 막을 예와 통과할 예를 하나씩 `jq` 의 `test` 로 확인하고 결과를 보고하라.
     훅은 명령에서 따옴표 구간(`'…'`, `"…"`)을 지운 뒤 맞춰 보므로, 예시 명령도 따옴표 구간을 지운 모양으로 넣어라.

     ```bash
     jq -n --arg re '<정규식>' --arg c '<막을 명령>' '$c | test($re)'    # true 여야 한다
     jq -n --arg re '<정규식>' --arg c '<통과할 명령>' '$c | test($re)'  # false 여야 한다
     ```

   - 사용자는 그 줄을 지워 규칙을 끈다.

### 제11조(폐지)

1. 사용자가 요청할 때만 폐지하라.
2. 먼저 시행 명부에서 빼는 것을 제안하라. 파일 삭제는 사용자가 명시적으로
   요청한 경우에만 하라.

## 제4장 반성문 장부 관리

### 제12조(장부 형식)

장부가 없으면 다음 머리말로 만들어라. 항목 형식은 골격의 〔공통〕 반성문 장부 기록
조문을 따른다.

```markdown
# 반성문 장부

> AI가 AI법을 어기고 스스로 기록한 반성문. 세션마다 자동 주입된다.
> 같은 위반을 다시 범하면 가중 위반이다.
```

항목 끝에 하네스가 기계적으로 집행하는 규칙 줄을 둘 수 있다. 줄 머리를 정확히 아래 모양으로
쓰고 한 줄에 규칙 하나를 둔다. 줄을 지우면 꺼진다(`- 검사:` 줄은 장부에 하나만 있어도 모든 작업에
적용되므로 같은 줄을 모두 지워야 꺼진다). `jq`(1.6 이상)가 없으면 아무 효과가 없다.

| 줄 | 효과 |
|---|---|
| `- 차단: <정규식>` | PreToolUse(Bash) 훅이 따옴표 구간을 지운 명령이 정규식(jq `test`)에 맞으면 실행 전에 거부하고, 그 항목의 「시정 및 재발 방지」를 사유로 보여 준다. |
| `- 검사: 한국어` | PreToolUse(Bash) 훅이 한글이 없는 `description` 을 거부하고, Stop·SubagentStop 훅이 코드를 뺀 최종 응답에 라틴 문자가 40자 이상인데 한글이 없으면 한 번 되돌려 한국어로 다시 쓰게 한다. |
| `- 검사: 비밀값` | PostToolUse(Bash) 훅이 stdout·stderr 에서 비밀값으로 보이는 값을 가린 뒤 모델에 넘긴다. |

### 제13조(장부 정리)

1. 사용자가 요청하면 장부를 정리하라.
   - 같은 조항·같은 원인의 항목을 합쳐라.
   - 오래된 경미한 항목은 `~/.claude/ai-lawbook/confessions-archive.md` 로 옮겨라.
   - 개인정보, 고객명, 비밀키, 사내 기밀이 적혀 있으면 일반화하라.
2. 항목을 옮기거나 지우기 전에 목록을 보여 주고 확인받아라.
3. 장부 전체가 6,000자를 넘거나 300자를 넘는 줄이 있으면 정리를 제안하라.
   재범 경위를 기존 줄에 덧붙이면 줄 수로는 커지는 것이 보이지 않고, 훅은 항목마다 제목·재범·시정·규칙
   줄만 추려 재범이 많은 순으로 3,500자(하위 에이전트는 3,000자)까지만 넣고 나머지는 건수로만 알리기 때문이다. 글자 수는 로캘과 무관하게 다음처럼 잰다(`wc -m` 은 C 로캘에서 바이트를 센다).

   ```bash
   LC_ALL=C tr -d '\200-\277' < ~/.claude/ai-lawbook/confessions.md | wc -c                               # 전체 글자 수
   LC_ALL=C tr -d '\200-\277' < ~/.claude/ai-lawbook/confessions.md | LC_ALL=C awk 'length > 300' | wc -l  # 300자 넘는 줄 수
   ```

## 제5장 시행 명부

### 제14조(명부 형식)

한 줄에 법 이름 하나를 적는다. `#` 뒤는 주석이다.

```text
# ~/.claude/ai-lawbook/enabled-laws
developer-ai-law
designer-ai-law   # UI 작업이 많아서
```

1. 명부에 적힌 법은 세션 시작, 재개, 컨텍스트 압축과 하위 에이전트 시작 때마다 주입된다(제8조 제3항의 상한 안에서).
2. 명부가 없거나 비어 있으면 법은 스킬 자동 호출로만 적용되고, 반성문 장부만 주입된다.
3. 법전에 없는 이름이나 본문이 빈 법을 명부에 적으면 훅이 세션 시작 상태 메시지로 알리고 건너뛴다.

## 제6장 판결

입법 작업을 마치면 마지막에 한 줄 판결을 추가하라.

```text
⚖️ AI 입법 판결: <제정|개정|폐지> 완료 — <법 이름> (조문 N개, 심사 통과)
```

심사에서 통과하지 못한 항목이 있으면 통과로 가장하지 말고 남은 항목을 적어라.
